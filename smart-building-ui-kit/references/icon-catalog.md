## dev- 設備本體

| 檔名 | 用途 | 必畫元素 | 避免 |
|---|---|---|---|
| `dev-intercom` | 室內對講機 | 直立面板外框 + 上方螢幕區 + 下方通話孔 | 不畫按鍵矩陣（太細） |
| `dev-intercom-outdoor` | 門口機 | 面板 + 上方鏡頭點 + 2×3 按鍵格 + 揚聲器孔 | 不畫門牌文字 |
| `dev-camera-dome` | 半球攝影機（室內） | 吊桿 + 半球罩 + 鏡頭點 | 不畫玻璃反光線 |
| `dev-camera-bullet` | 槍型攝影機 | 支架 + 長筒機身 + 前端鏡頭 | 不畫螺絲、線材 |
| `dev-access-reader` | 門禁讀卡機 | 面板 + 右側感應弧 + 卡片輪廓 | 不畫 LED 小燈點排 |
| `dev-reader-uhf` | UHF 長距離讀頭 | 長方體 + 兩道方向性波束 | 不畫車牌、不畫標籤天線細節 |
| `dev-lock` | 電子鎖 | 門板邊緣 + 鎖舌 + 鑰匙孔 | 不畫整扇門與門框 |

## 新圖示的衍生規則

清單裡沒有的設備，照這個順序處理：

1. **先找骨架，不要從零開始。** 中控設備幾乎都能歸進五種骨架：方盒類（面板、機櫃、機身）、圓形類（表盤、風扇、燈）、半球類（攝影機、感測器）、人形類（訪客、人員類）、波形類（訊號、感測、通訊）。沿用同骨架的既有圖示，只換內部符號——這樣新圖示天生就和舊的一致。
2. **命名沿用既有 domain。** 不知道放哪就選最接近的；真的新領域才新增前綴，並同步更新 `svg_lint.py` 的 `DOMAINS`（否則 lint 會判檔名錯誤）。
3. **品牌專屬設備**（例如公司的對講機型號外觀）用型號當名尾：`dev-intercom-ip8810`。但要先問一句：這顆圖示需要一眼認出「是我們家那台」嗎？多數中控介面不需要，用通用版更好認。
4. **一個概念要塞三顆圖示才講得清楚＝概念切錯了。** 拆成兩顆不同設備，或改成一顆圖示 + 狀態色。
